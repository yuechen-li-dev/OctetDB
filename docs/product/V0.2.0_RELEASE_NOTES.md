# OctetDB v0.2.0 release notes

OctetDB v0.2 makes the catalog/dataset model the default public Go workflow.
Applications open one directory, declare Database → Bucket → Dataset topology,
store ordinary structs, and submit stable database-wide command IDs.

## Added

- Sane-default keyed Go state through `OpenCatalog` and `Database`.
- Durable Bucket/Dataset catalog with stable database and dataset identities.
- Dataset-scoped record identity and fail-closed kind/type/bound checks.
- One atomic `Database.Mutate` transaction that can span datasets.
- Exact accepted/rejected command decisions within a bounded database-wide
  dedupe horizon.
- Deterministic `Dataset.Scan` and typed `ScanDataset[T]`, including ascending
  keys, stable snapshots, detached values, cancellation, and early stop.
- Canonical quickstart and four external golden applications covering inventory,
  webhooks, order lifecycle, jobs, low-stock discovery, and ready-job discovery.
- Separate optional Oct query example for `filter`/`map`/`take` and FLOW-backed
  terminal behavior.

## Compatibility

- The v0.1 `Open`/`DB` account API and `accounts-v1` directories remain
  supported.
- The unreleased pre-v0.2 `OpenKeyed`/`KeyedDB` global-key API is deprecated but
  can still open its distinct `keyed-json-v1` directories.
- New v0.2 databases use `catalog-keyed-json-v1`. Formats are not silently
  migrated or reinterpreted.
- Oct is optional and is not a runtime or compiler dependency of the Go module.
  The advanced example is verified against Oct revision
  `ca22ab8dfc20ac6d6c59dd34976789cd2c84ad2e`; generated host ABI stability is
  not promised across Oct revisions.

## Defaults

100,000 live records, 100,000 retained command decisions, 1 MiB per encoded
value/result, and 4 MiB of writes per command. Dataset bounds inherit the
database defaults. Keys and command IDs are limited to 4 KiB and rejection
codes to 1 KiB.

## Known limitations

Single process and replica; no directory lock, SQL, secondary indexes, joins,
MVCC, replication, automatic migration, schema reflection, online backup, or
large-blob path. Scans hold the database admission boundary and therefore block
mutations for their duration. Idempotency is exact only while an ID remains in
the configured horizon. Windows snapshot-rename power-loss guarantees are
weaker than POSIX directory-sync behavior.
