# OctetDB v0.1.0 release notes

OctetDB is an embeddable, single-process OLTP engine for a deliberately bounded
account and transfer domain. Applications submit commands with stable IDs, read
authoritative account state, and recover durable decisions after restart.

## Install

Requires Go 1.23 or newer.

```sh
go get github.com/yuechen-li-dev/octetdb@v0.1.0
```

```go
db, err := octetdb.Open(context.Background(), octetdb.Options{Path: "./data"})
if err != nil {
    log.Fatal(err)
}
defer db.Close()

_, err = db.Submit(context.Background(), octetdb.Command{
    ID: "create-1", Kind: octetdb.Create, AccountID: 1, Amount: 100,
})
```

## Durability

A successful submission means its complete checksummed WAL frame has been
written and synchronized. Recovery validates the format marker, restores an
optional snapshot, and replays the complete WAL tail. Retrying a retained
command ID returns the original durable decision without applying it twice.
The full contract is in [DURABILITY.md](../DURABILITY.md).

## Supported v0.1 scope

- create, deposit, withdraw, transfer, freeze, and unfreeze accounts;
- begin, confirm, or cancel a two-step transfer;
- single-process, single-replica embedded operation;
- bounded accounts, offered batches, and exact dedupe retention;
- snapshots and snapshot-plus-WAL recovery.

## Known limitations

- No SQL, network server, replication, failover, schema migration, online
  backup API, directory lock, or user-authored model surface.
- Command-ID deduplication is exact only within the configured horizon.
- Pre-1.0 API and database formats may change between minor releases; automatic
  migration is not promised, but incompatible data is rejected.
- Snapshot rename power-loss guarantees are weaker on Windows than POSIX.
- Windows and Linux under WSL2 are tested; macOS is not yet verified.

## Performance evidence

In a bounded single-replica local OLTP experiment, the specialized safe-Go
engine that became the v0.1 product engine exceeded the measured
single-replica TigerBeetle control in the tested configurations. The systems
were not guarantee-equivalent, and the result is not a general database
benchmark. See [TigerCompareM0](../experiments/TIGER_COMPARE_M0.md) for the
workload, environment, results, and limitations.
